04 · Xâm nhập Web — OWASP Top 10 qua lăng kính lab SecLab

Khác với tấn công Phủ nhận Dịch vụ (chuyên mục 02) nhắm vào độ sẵn sàng, tấn công ứng dụng web nhắm vào dữ liệu và quyền kiểm soát. Danh sách OWASP Top 10 (Open Worldwide Application Security Project) tổng hợp mười nhóm rủi ro web phổ biến nhất. Chuyên mục này giải thích cơ chế từng nhóm, cách phòng và đối chiếu với 15 lỗ hổng được cài cố ý trong lab SecLab — src/lab/app.js với hai chế độ vuln (cố ý dễ tổn thương) và hardened (đã vá). Bản đồ đầy đủ LAB→OWASP→CWE nằm ở docs/08-owasp-top10-mapping.md.

⚠️ Cảnh báo pháp lý

Toàn bộ nội dung chỉ phục vụ hiểu và phòng thủ, thực hành duy nhất trên lab tại 127.0.0.1. Quét, dò, can thiệp hệ thống của người khác là phạm tội theo Điều 287 Bộ luật Hình sự 2015 — mọi lệnh SecLab vì vậy đều kiểm duyệt mục tiêu qua src/guard.js và chặn cứng địa chỉ public.

Cơ chế các nhóm lỗ hổng trọng tâm

  • SQL Injection — đầu vào được nối chuỗi thẳng vào câu truy vấn, khiến dữ liệu bị CSDL hiểu nhầm là lệnh. Dạng boolean-based chèn điều kiện luôn đúng để trả về toàn bộ bảng; dạng error-based gây lỗi SQL để đọc thông báo lỗi, dò cấu trúc bảng.
  • XSS — Cross-Site Scripting: chèn JavaScript chạy trong trình duyệt nạn nhân. Reflected: input được in lại nguyên văn trong response (kể cả trang 404); stored: dữ liệu độc được lưu vào CSDL rồi hiện ra cho mọi người; DOM-based: script phía client tự chèn dữ liệu không an toàn vào DOM.
  • IDOR — Insecure Direct Object Reference, thuộc A01 Broken Access Control: tham số định danh (/api/users/2) được tin mà không kiểm tra người gọi có quyền — đổi số ID là đọc được dữ liệu người khác.
  • SSRF — Server-Side Request Forgery: lừa server chủ động truy cập URL do kẻ tấn công chỉ định để đọc dữ liệu nội bộ. SecLab tự chống SSRF bằng cách kiểm duyệt mục tiêu hai lần — tại entry (src/cli.js:206) và trong module quét (src/modules/vulnscan.js:4).
  • Path Traversal — dùng ../ "đi lên" khỏi thư mục gốc để đọc file bất kỳ trên máy chủ.
  • Broken Authentication — nhóm A07: vượt qua xác thực (nhờ SQLi ở câu đăng nhập), cookie phiên thiếu cờ bảo mật, thông báo lỗi xác thực quá chi tiết.
  • Misconfiguration — nhóm A05: stack trace lộ ra response, directory listing còn bật, thiếu bộ security headers (CSP — Content Security Policy: header ra lệnh cho trình duyệt chỉ được tải script/ảnh/style từ các nguồn được liệt kê, chặn nốt script độc chèn qua XSS; X-Frame-Options: cấm trang bị nhúng trong iframe của site khác).
  • Command Injection — cùng nhóm A03 Injection như SQLi nhưng đích đến là shell hệ điều hành: input được nối thẳng vào exec(), nên dấu nối lệnh (&, ;, |) kéo theo lệnh thứ hai. Đây là lỗ hổng nguy hiểm bậc nhất — rơi thẳng vào Remote Code Execution.
  • CSRF — Cross-Site Request Forgery: form đổi dữ liệu không có token chống giả mạo, nên một trang độc trên domain khác có thể khiến trình duyệt nạn nhân tự gửi request kèm cookie phiên. Phòng thủ chuẩn là synchronizer token + kiểm tra Origin — chuyên mục 05 giải thích thêm cờ SameSite.
  • JWT yếu — token xác thực ký bằng secret dò được (secret123) hoặc chấp nhận alg=none "không cần ký": kẻ tấn công tự forge token admin mà không cần mật khẩu. Nhóm A02 Cryptographic Failures.
  • Open Redirect — endpoint /redirect?to= tin tưởng URL đích do client truyền, chuyển hướng tới domain bất kỳ — bệ phóng hoàn hảo cho phishing ("link từ domain quen thuộc nhưng đáp xuống trang giả").
  • Unrestricted Upload — cho tải mọi loại file rồi phục vụ lại nguyên trạng: upload .html chứa script được serve đúng text/html là có ngay stored XSS tự tạo; ngoài đời còn dẫn tới webshell, tràn đĩa.
  • XXE — XML External Entity: parser XML xử lý <!ENTITY x SYSTEM "file:///..."> đọc file nội bộ và nhúng vào dữ liệu. Lab mô phỏng an toàn tuyệt đối trên filesystem ảo — cơ chế tấn công thật, hậu quả thật bằng không.

Bốn trụ cột phòng thủ

1 Parameterized query

SQL giữ chỗ ?, giá trị truyền riêng biệt — CSDL không bao giờ trộn lẫn lệnh và dữ liệu. Trong lab: searchUsersSafe(), loginSafe() (src/db.js:55,77). Nguyên tắc vàng: không nối chuỗi input vào SQL.

2 Output encoding

Trước khi in dữ liệu động ra HTML, mã hoá ký tự đặc biệt (< > & " ') theo đúng ngữ cảnh — hàm esc() (src/lab/app.js:27). Khi đó script chèn vào chỉ hiện như văn bản; kết hợp CSP để chặn nốt nguồn script ngoài.

3 Kiểm tra quyền trên server

Mọi endpoint tự hỏi "đối tượng này thuộc về ai?" dựa trên phiên đăng nhập phía server, không tin tham số URL. Bản hardened trả 401/403 (src/lab/app.js:274-278); thông báo sai mật khẩu viết chung chung để không dò ra tài khoản hợp lệ.

4 Allowlist

Chỉ chấp nhận giá trị trong danh sách trắng: đường dẫn tải file phải bắt đầu bằng files/ và không chứa ..; mục tiêu quét phải thuộc phạm vi ủy quyền (loopback tự do, dải riêng cần --i-own-this-target, public chặn). Từ chối mặc định phần còn lại — hiệu quả với cả SSRF lẫn path traversal.

Quan sát bằng lệnh scan

npm run serve                                  # lab vuln :3000
node src/cli.js scan http://127.0.0.1:3000     # quét SQLi, XSS, IDOR, headers…
npm run serve:hardened -- --port 3001          # bản đã vá — bắt buộc port khác để chạy song song
node src/cli.js scan http://127.0.0.1:3001     # so sánh trước/sau vá

lab Scanner src/modules/vulnscan.js gửi 14 nhóm probe kiểm chứng: so số dòng kết quả giữa hai giá trị tìm kiếm để phát hiện SQLi boolean-based (src/modules/vulnscan.js:10-48), kiểm tra security headers còn thiếu (src/modules/vulnscan.js:82-105), thử nối lệnh ở /tools/ping (CMDI), gửi form CSRF không token, forge JWT alg=none, kiểm redirect tới domain ngoài, upload .html thử, POST XML có DOCTYPE và cài payload stored XSS ở guestbook. Mỗi finding kèm mức độ, bằng chứng, cách vá; báo cáo .md/.html ghi vào reports/ (src/cli.js:244-255). Bản vuln thật báo 10 High + 4 Medium (SQLI, XSS reflected+stored, CMDI, CSRF, JWT, OREDIR, UPLOAD, XXE, IDOR); cùng lệnh trên bản hardened hầu hết chuyển sang "Đạt" — vì vá nằm ở lớp server-side, đúng chỗ dữ liệu và lệnh trộn lẫn. Làm sâu hơn theo exercises/03-quet-lo-hong.md, exercises/04-tan-cong-lab.md, exercises/10-13 (bảy lỗ hổng mới) và exercises/06-phong-thu-va-bao-cao.md.

Điểm cần nhớ

  • SQL Injection, XSS, IDOR, SSRF, Path Traversal chung một gốc: dữ liệu người dùng bị coi là lệnh hoặc tin tưởng quá mức — vá ở điểm trộn dữ liệu/lệnh, đừng chỉ lọc payload.
  • Bốn trụ cột phòng thủ web: parameterized query, output encoding, kiểm tra quyền trên server theo phiên, allowlist.
  • Lab chứa 15 lỗ hổng LAB-01→LAB-15 trong src/lab/app.js; node src/cli.js scan (14 probe) trên cả hai chế độ cho thấy khác biệt trước/sau vá — bản vuln thật báo 10 High + 4 Medium.
  • Security headers, cờ cookie, rate limit chỉ là lớp bổ sung, không thay thế bốn trụ cột.
  • Thực hành chỉ trên 127.0.0.1; quét hay khai thác hệ thống người khác vi phạm Điều 287 BLHS 2015.
